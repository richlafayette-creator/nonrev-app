# Nonrevy i18n Foundation

Nonrevy currently uses a lightweight internal i18n layer instead of locale-based routes. This preserves the existing routing behavior while giving shared UI labels a single translation source.

## Current locales

- `en` — English, the default locale
- `es` — Spanish
- `ja` — Japanese

## Files

- `messages/en.json` — default English strings
- `messages/es.json` — Spanish starter strings
- `messages/ja.json` — Japanese starter strings
- `lib/i18n/messages.ts` — locale list, message imports, fallback helper, shared translation key types
- `app/I18nProvider.tsx` — client provider, `useI18n()` hook, and locale-aware date/time formatter

## Adding a new locale

1. Copy `messages/en.json` to `messages/<locale>.json`.
2. Translate the existing keys without renaming them.
3. Add the locale code to `locales` in `lib/i18n/messages.ts`.
4. Add a human-readable label to `localeLabels`.
5. Import the new JSON file and add it to the `messages` map.
6. Run validation:
   - `git diff --check`
   - `npx tsc --noEmit`

## Adding new shared strings

1. Add the English key to `messages/en.json` under the `common` namespace.
2. Add matching keys to every starter locale file.
3. Use `const { t } = useI18n()` in client components and render `t('<key>')`.
4. Keep keys readable and scoped to shared/common UI labels. Do not move large feature-specific copy until a dedicated translation sprint.

## Current boundaries

- Default language remains English.
- No locale-prefixed routing has been added.
- Provider integrations, itinerary generation, and scoring behavior are unchanged.
- Only common/shared labels from the i18n foundation sprint have been moved.
